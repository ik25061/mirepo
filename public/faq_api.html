❓ Preguntas frecuentes FAQ
¿Qué es userId y por qué muchas rutas lo piden?
Es el ID numérico del usuario (lo devuelve /api/auth/login). Se usa para personalizar la biblioteca: canciones que te gustan, artistas favoritos, artistas ocultos y playlists. Si no lo pasas, la API devuelve los datos sin personalización (modo anónimo).
¿Cómo obtengo el id de una canción para usar /audio/:id o /cover/:id?
Haz una petición a /api/library o /api/artists/:id/songs. Cada canción trae un campo id (cadena hexadecimal). Ese mismo id se usa en /audio/:id, /cover/:id, /api/lyrics/:id, /api/songs/:id/like, etc.
¿Por qué /api/library puede devolver un error 503?
Porque la biblioteca aún se está cargando en memoria cuando arranca el servidor (el campo libraryReady de /api/test será false). Espera unos segundos y vuelve a intentarlo. La mayoría de las otras rutas consultan SQLite y no tienen este retraso.
¿Cómo hago streaming de audio con barras de progreso y seek?
El endpoint /audio/:id soporta peticiones HTTP Range (bytes) y responde con 206 Partial Content, Content-Range y Accept-Ranges: bytes, así que un elemento <audio> puede hacer seek y mostrar progreso sin problema. Es el mecanismo que usa el reproductor de Mirepo.
¿Qué significan los códigos de estado que devuelve la API?
200 OK · 206 contenido parcial (streaming con Range) · 400 faltan datos (p. ej. userId en liked-songs) · 401 token inválido · 404 recurso no encontrado (canción, artista, playlist…) · 409 conflicto (usuario ya existe) · 503 biblioteca aún cargando · 500 error interno.
¿Hay límites de paginación?
Sí. Las rutas que aceptan limit lo limitan a un máximo de 100 resultados por página aunque pidas más. Usa offset o la propiedad hasMore de la respuesta para recorrer todas las páginas.
¿Cómo autenticarme para probar los endpoints de usuario?
1) Registra un usuario en POST /api/auth/register (o inicia sesión en POST /api/auth/login). 2) La respuesta trae user.id y token. 3) Usa user.id como userId en el resto de rutas. El token solo hace falta en /api/auth/verify y /api/auth/logout.
¿Esta página funciona en mi móvil?
Sí, siempre que estés en la misma red: abre http://IP_DEL_PC:5172/faq_api.html. Las peticiones usan rutas relativas, así que van al mismo host/puerto desde el que abriste la página (Vite hace de proxy hacia Express). Si abres el archivo directo desde el disco no funcionará.
